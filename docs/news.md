# お知らせの管理

## 操作

1. `/admin` にログインし、メニューの「お知らせ」を開く。
2. 「お知らせを作成」からタイトル・日付・ジャンル・タグ・URL・本文を入力。本文は文字を選択して文字サイズ・太字・下線・リンクなどを設定でき、見出し・リスト・引用・区切り線にも対応。プレビューで公開時の書式を確認できます。
3. 画像はJPEG/PNG/WebPを選択、またはHTTPSのURLやサイト内パスを指定。
4. 「公開する」をチェックして保存すると、トップの最新3件・一覧・詳細に反映。
5. 非公開にするときはチェックを外して保存。下書きは公開APIにも詳細URLにも出ない。

一覧ではジャンルとタグで絞り込めます。日付降順、同日なら更新日時の降順です。
日付は表示・並び順のためのもので予約投稿機能ではありません。
公開後はURLをなるべく変更しないでください。過去URLからのリダイレクトはありません。
ページの再読み込みで最新内容を表示します（開いたままのページへの自動配信ではありません）。

## ローカル確認

`npm run dev` → http://localhost:3003/#news
管理画面: http://localhost:3003/admin/news

Supabaseのサーバー環境変数がない開発環境では `.local/news.json` に保存します。
ファイルがない初回だけ4件の明示的なサンプル記事を読み込みます。
このファイルはGit管理外で、本番には公開されません。

## 本番への接続（デプロイ前に必要）

1. 保存先Supabaseで `supabase/schema-news.sql` を実行する。
2. サーバー環境変数 `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` を設定する。
3. 管理セッションの `ADMIN_API_SECRET` を十分に長いランダム値で設定する。
4. 既存の管理画面にログインして実際の記事を作成する。

本番にはサンプルを自動投入しません。保存先未設定・DBエラー時にローカル保存へ切り替えることもありません。
画像は長辺1400px以内に縮小して記事と一緒に保存します（圧縮後約650KBまで）。
DBはRLSを有効にし、anon/authenticatedの直接アクセスは許可しません。
管理APIは既存の署名付きHttpOnlyセッションと同一オリジン検証を利用します。
複数画面から同じ記事を保存した場合は更新日時で競合を検出します。

## Cookieについて（今回の実装範囲外）

現状はGA4、Clarity、Vercel Analyticsを使用しています。バナーを追加する際は
「許可する」「必要なもののみ」を選べるようにし、GA4・Clarityの読み込み自体を
同意取得後に行うことを推奨します。設定の変更・撤回、プライバシーポリシーの説明も合わせて整備します。
単に「同意する」を表示するだけでは解析タグの制御にはなりません。

本文は既存のbody欄にバージョン付き構造データとして保存します。旧形式のプレーンテキストも表示・編集可能です。公開時は許可した要素のみReactで描画し、生HTMLは実行しません。
